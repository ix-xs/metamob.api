# Documentation site

An [Astro Starlight](https://starlight.astro.build) site for `@ix-xs/metamob.api`, published at <https://ix-xs.github.io/metamob.api/>.

| Section | Source |
| --- | --- |
| Start, Basics, Resources, Recipes | `src/content/docs/<section>/`, one page per topic, written by hand |
| Every method | `src/content/docs/reference/methods.md`, generated by `scripts/reference.mjs` from `../scripts/api.config.mjs` |
| Error codes, All exports, Runtimes, Troubleshooting, FAQ | `src/content/docs/reference/` and `help/`, written by hand |
| The playground of the landing page | `src/components/NameFinder.astro`, which runs on the library's own data set |
| The French version | `src/content/docs/fr/`, the same pages at the same paths |

## How a page is written

Each topic has exactly one page, and each fact has one home: a page links to the page that owns something instead of explaining it again.

A page has the same shape everywhere:

1. Frontmatter: `title`, and a `description` of one or two sentences. The description is shown as the lead paragraph under the title, so it says what the page lets you do. Pages of an autogenerated section also carry `sidebar: { order: n }`. A value that contains a colon followed by a space goes in double quotes, or YAML rejects the page.
2. A first example, before any heading: the shortest code that shows the point of the page.
3. One `##` section per need, named after what the reader wants to do ("Recording a monster"), not after an API name.
4. `## Reference`: tables of the options, methods or values the page covers.
5. Limits and errors where they matter: what the API refuses and which `error.code` to expect.
6. `## See also`: three or four links.

Style:

- Short sentences, plain words, second person. Say what happens, then why. No filler, no marketing adjectives, no emoji.
- No long dashes. Use a comma, a colon or a new sentence. `npm run lint:prose` at the repository root enforces it.
- The API allows 60 requests a minute: say how many requests a recipe or a loop costs wherever it matters.
- Examples use monsters, zones and servers that exist. A username in an example is `Ix-xs` or the `username` placeholder, never another real player.
- Facts come from the source code in `../src`, not from memory. Doc comments there are the reference for behaviour, defaults and costs.

## Code samples

Every ` ```ts ` block is compiled against the library by `npm run check-samples`, so a page cannot show code that does not type-check.

- A block is one module. Imports from `@ix-xs/metamob.api` resolve to the source.
- A name the package exports (`Metamob`, `data`, `urls`, `isMetamobError`...) can be used without importing it. Show the import when the block is a complete program or introduces the name for the first time on the page.
- `metamob` (a client), `base` (the single client of a bot), and placeholders such as `slug`, `username`, `apiKey`, `theirKey`, `signal`, `db` exist everywhere. The full list is at the top of `scripts/check-samples.mjs`.
- A line that must not compile is written with `// @ts-expect-error` and the reason. The check then proves the claim.
- ` ```ts nocheck ` skips a block. Keep it for fragments that cannot stand alone.
- Other languages (`bash`, `js`, `json`) are not checked.

```bash
npm run check-samples            # every page
npm run check-samples basics     # only pages whose path contains "basics"
```

## Writing links

Write internal links root-relative, without the base path:

```md
[the rate limit](/basics/rate-limit/#watching-it)
```

[`plugins/base-links.mjs`](./plugins/base-links.mjs) prepends the base at build time, in Markdown links and in the `href` of MDX components alike. `npm run check-links` verifies every link and anchor of the built site.

## Translations

English is the original: its pages sit at the root of `src/content/docs/` and of the site. The French version mirrors them in `src/content/docs/fr/`, at the same paths, and is served under `/fr/`. A page without a translation falls back to English with a notice.

A translation changes the prose and nothing else:

- The same frontmatter keys, headings (same number, same levels, same order), code blocks and link targets as the English page. Comments inside code may be translated.
- Links are copied as they are, without `/fr`: the build adds the language. Anchors are the English ones too, because a translated heading gets the id of its English counterpart ([`plugins/heading-ids.mjs`](./plugins/heading-ids.mjs)). So `[la limite de requêtes](/basics/rate-limit/#watching-it)` is right on a French page.
- In an `.mdx` page, a relative import gains one `../`.
- French addresses the reader as "vous", puts a space before `:`, `;`, `?` and `!`, and keeps the names of the API (`slug`, `status`, a method name) as they are in code.

```bash
npm run check-translation            # every translated page mirrors its original
npm run check-translation fr/basics  # only the pages under a folder
```

After changing an English page, change its translation in the same commit: the check fails when the two no longer have the same shape, and the deploy workflow runs it.

The words of the interface itself (header, search, landing page, playground) are in [`src/i18n.ts`](./src/i18n.ts), one dictionary per language. Adding a language means a dictionary there, a folder of pages, an entry in `LOCALES` of [`plugins/base-links.mjs`](./plugins/base-links.mjs) and in `locales` of `astro.config.mjs`, and the words of the generated pages in `scripts/reference.mjs`.

## Generated pages

After changing an endpoint or its description in `scripts/api.config.mjs`:

```bash
npm run reference
```

and commit the result. `node scripts/reference.mjs --check` fails when a generated page is out of date; the deploy workflow runs it.

The page is written in each language. Its own words are translated in the script. What describes a method comes from the config, in English, and its French is in `scripts/reference.fr.json`, keyed by the English sentence: after adding or rewording a description, the script stops and lists the sentences left to translate. An entry that translates nothing any more must be removed, the script says which. The French page names each guide by the title of its French page, so run the script again after translating a title.

## Develop

```bash
cd docs
npm install
npm run dev        # serves http://localhost:4321/metamob.api
```

## Build and check

```bash
npm run build           # static site in docs/dist
npm run check-links     # every internal link and #anchor must resolve
npm run check-samples   # every TypeScript sample must compile
npm run check-translation   # every translated page must mirror its original
```

After changing a plugin in `plugins/`, delete `docs/.astro` and `docs/node_modules/.astro` as well: rendered pages are cached.

After changing the code theme (`src/styles/code-themes.mjs`), delete `docs/.astro` and `docs/node_modules/.astro` before building: pages rendered from the local cache keep linking to the previous stylesheet of the code blocks. A fresh checkout, as in the deploy workflow, is not affected.

The playground of the landing page can be opened on any input, to look at the cases that are tedious to type: `FINDER_START="Crognan le Barbare" npm run dev` (a shared name), `FINDER_START="Tofu Malefik"` (a typo), `FINDER_START=""` (nothing). A normal build ignores the variable.

The site icon is drawn in `public/favicon.svg`. After changing it, run `node scripts/icons.mjs` and commit the two PNG files it writes.

## Hosting it somewhere else

The site URL and base path come from two environment variables:

| Variable | Default | Meaning |
| --- | --- | --- |
| `DOCS_SITE` | `https://ix-xs.github.io` | The origin the site is served from |
| `DOCS_BASE` | `/metamob.api` | The path under that origin (`/` for the root) |

```bash
DOCS_SITE=https://docs.example.dev DOCS_BASE=/ npm run build
```

On GitHub, set them as repository variables (Settings > Secrets and variables > Actions > Variables): [the workflow](../.github/workflows/docs.yml) passes them through, and falls back to the defaults when they are unset. No content has to change.
